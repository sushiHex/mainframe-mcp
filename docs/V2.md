# Mainframe Daemon

v2 runs one local service for indexing, search, and capture across MCP clients.
`mainframe-mcp` connects stdio clients to this daemon. Harrier BF16 and the
Qwen3-Reranker-0.6B BF16 is the default reranker. It uses the pinned default
technical-documentation `<Document>` contract, a 2,048-token joint budget,
saved-order batches of eight, and three returned passages by default. The
selection evidence is documented separately; it is not a production replay,
daemon smoke, or CI result. v2 supports capture, indexing, and search;
consolidation, contradiction detection, and RAPTOR remain v1 features.

## Configure and start

Install with `python -m pip install -e ".[test]"`. Configure project scope before
starting: an empty `paths.include_projects` includes every eligible repository
under `paths.repos_dir`. Includes and excludes accept project-name globs.

A minimal configuration for an isolated deployment:

```json
{
  "paths": {
    "mainframe_dir": "~/.local/share/mainframe-v2",
    "repos_dir": "~/repos",
    "include_projects": ["example-project"]
  },
  "service": {"port": 7433}
}
```

Point `MAINFRAME_CONFIG` at that JSON file in every server and client shell.
For example, PowerShell uses `$env:MAINFRAME_CONFIG = "./config.json"`; POSIX
shells use `export MAINFRAME_CONFIG=./config.json`. Paths expand `~`. Without
an override, configuration lives at `~/.claude/mainframe/config.json`.
Invalid JSON and unknown configuration keys prevent startup. Hardware presets
in `configs/` can be selected through `MAINFRAME_PRESET` in a source checkout.

```bash
mainframe serve
# In another shell with the same configuration:
mainframe status
mainframe search "embedding batch size" --detailed
mainframe events --tail 20
mainframe down
```

Models load on demand; `service.prewarm: true` loads them at startup. Health
checks stay responsive during model loading. `mainframe serve` works on Windows
and POSIX. Windows users using the default configuration location can install
a logon task with `mainframe install-task` and start it with `mainframe up`.
Use `mainframe install-task --dry-run` to write and inspect the task XML first.

## Scoped project trial

Start with an explicit project scope. The standard Harrier stack is already
selected; [v2-harrier.json](../configs/v2-harrier.json) makes its contract
explicit. Set `service.token` for authenticated clients and keep configuration
outside Git. Installed wheels accept JSON configuration; named presets require
the source checkout. Environment model/path overrides take precedence. A
model-only `MAINFRAME_EMBEDDER_MODEL` override uses legacy Sentence Transformers
encoding. Select a native embedder in JSON or a preset and provide its model,
`encoding`, pinned `revision`, `query_prompt`, and `quantize` settings together.

When replacing the former Qwen embedder, stop the daemon and rebuild its
disposable index offline, or select an existing Harrier index with the same
recorded contract. Source notes and captures remain authoritative. Retaining
the former model is not a requirement. Measure system commit and GPU headroom
on your normal workload.

After synthetic validation, run `mainframe serve` with the private configuration.
Across separate client sessions, answer real project questions, inspect source
citations, capture a useful decision, and recall it with sessions enabled after
restart. Confirm ordinary search hides captures and unchanged files are reused.
Keep a private record of errors and missed answers over subsequent work sessions
before widening scope. A short scripted trial does not establish multi-day stability.
Stop with `mainframe down` using the same configuration to release GPU memory.

### Everyday Harrier evaluation

The [native Harrier configuration](../configs/v2-harrier.json) describes the
default stack. Start with an explicit project list. To widen it, stop
the daemon, add one project to `paths.include_projects`, and restart; unchanged
documents are reused. Check `mainframe status` and recent events after indexing.

Keep a private question journal outside every Git checkout. Record the original
question and its author before searching; when already known, include the
expected source, a short exact answer excerpt, and the source's content hash.
Then record the result, citations, model/configuration identity, and a hit/miss
assessment. Label agent-authored probes separately. Assessments added after
seeing results are useful regression cases, not independent holdout evidence.
Freeze new user-authored questions before using them for a model comparison.

Use `mainframe search` for unrecorded searches and `mainframe down` to release
the models when finished. Ordinary project use and checked source answers are
the next evidence to collect; another broad model sweep is unnecessary.

## Connect clients

Register `http://127.0.0.1:7433/mcp` as a Streamable HTTP MCP server, using the
configured port. The full endpoint exposes `search`, `capture`, `status`, and
`maintain`. `/mcp/ro` exposes only `search` and `status`.

For hosts that require stdio:

```bash
python -u -m mainframe.adapters.mcp_stdio_shim
```

The shim forwards to the full `/mcp` endpoint without loading another set of
models. Use HTTP `/mcp/ro` when the client needs read-only access. v1's
`MAINFRAME_READ_ONLY` and `MAINFRAME_PREWARM` variables do not configure v2.

A shim outlives daemon restarts. With `service.port` left at 0 the daemon takes
a new ephemeral port each start, so the shim re-reads discovery and resends the
request when its cached address stops accepting connections. Restarting the
daemon under a running client costs that client nothing, and a request is
resent only when the failure proves it was never delivered. When the daemon is
genuinely down, the client is told to run `mainframe up`.

The REST surface includes `GET /healthz`, `/status`, `/events` and
`POST /search`, `/capture`, `/jobs/{kind}`, `/shutdown`. Maintenance jobs are
`index`/`rescan`, `optimize`, and `reload`; `index` aliases `rescan`.

The service binds to loopback and checks the Host header. Browser requests
must carry the daemon's own origin (same scheme, hostname, and port); requests
from other origins receive HTTP 403 before REST or MCP dispatch. Native clients
can omit Origin. On shared machines, set `service.token`; all routes then
require `Authorization: Bearer <token>`.
The CLI and shim read that token from configuration; HTTP MCP clients must send
the header themselves. Keep configuration and event logs outside public Git.

## Files, captures, and citations

Markdown files are authoritative. The knowledge lane discovers root context
files, documentation, research notes, and the local library. Project filters
and symlink containment checks apply during scans and watcher processing.

`mainframe capture --file note.md --project example-project --title "Decision"`
writes an immutable, secret-scrubbed capture under
`<mainframe_dir>/captures/<project>/`. The watcher indexes it after debounce;
periodic rescans recover missed notifications. Captures are excluded from
ordinary search; opt in with `--sessions` or `include_sessions=true`.

Search returns `reranked` and reranker scores. `reranked` is a boolean: `false`
when nothing ranked the results — an empty result set, or a reranker disabled
via `reranker.enabled: false` (candidate order only, every score `0.0`) —
`true` otherwise. Models load on demand — the first search after a restart
may be slow — but a search always ranks its results or fails; it never
returns results silently unranked. Detailed results include text,
character offsets, and truncation status; `response_format="full"` returns the
whole chunk for evaluation. Line citations require a matching file revision
and a verifiable passage. Ambiguous or changed passages receive no line span.
Existing merged-heading captures can regain correct spans without reindexing.

## Index ownership and recovery

v2 uses `<mainframe_dir>/index.lancedb`; v1 continues using `.lancedb`. The first
v2 start builds a fresh index. A process lock excludes concurrent daemon and
offline writers. Mutations run through one queue; shutdown retains ownership
until the active writer finishes. A second instance exits with code 3.

The index records the settings that produced it. Changed index settings block
indexing and appear in `status.index.config_drift`; embedding changes also
block incompatible searches. Update configuration, then use:

```bash
mainframe down
mainframe rebuild
mainframe serve
```

Rebuild drops and recreates only the v2 index. It refuses while a daemon owns
the lock. Restart after configuration edits; `mainframe reload` releases
models and clears load-failure backoff, rather than rereading configuration.
Recognized device failures trigger one model reload and retry. Repeated load
failures back off, while file and job failures remain visible in events.

Native Qwen reranking computes vocabulary logits only for the final token;
the full prompt still participates in attention, and the unused decoder cache
is disabled. The default uses Qwen3-Reranker-0.6B in BF16 at revision
`e61197ed45024b0ed8a2d74b80b4d909f1255473`, its `<Document>` technical-
documentation instruction, a 2,048-token joint budget, and saved-order batches
of eight. Restart after changing a reranker setting. The score orders passages
within a response; it is not calibrated correctness confidence. See the
[reranker comparison](RERANKER_COMPARISON.md) before changing contracts: lower
memory or latency alone does not establish retrieval parity.

After the reranker loads, `status.models.reranker.info` reports its actual
`backend`, `precision`, `revision`, and `batch_size`. A reranker model override
clears the inherited default revision so the old pin cannot be applied to a
different checkpoint; configure an explicit replacement revision when a pin is
required.

Automatic offline loading requires every enabled model's configured revision
to be cached. An older snapshot alone does not satisfy a new revision pin.
An explicitly set `HF_HUB_OFFLINE` takes precedence; unset it when missing
weights need to download.

## Native embedding contract

The default v2 path uses `embedder.encoding: "native"`,
`embedder.quantize: false`, and a full 40-character `embedder.revision`.
It loads the pinned model in BF16 with SDPA and uses Sentence Transformers'
`encode_document` and `encode_query` routes with normalized output. A saved
query prompt with a nonstandard name can be selected through
`embedder.query_prompt` (for example, Harrier's `web_search_query`). The model's
document prompt and pooling remain intact. Native queries use no legacy Qwen
category prefix.

A normal installation includes the native dependencies. The path checks for Sentence
Transformers 5.4.1+ and Transformers 5.7.0+ before selecting a device. Unpinned
revisions, quantized native loading, invalid context limits, and an inability
to enforce the recorded context limit fail explicitly. Custom model code
requires a reviewed adapter; the generic path refuses an automatic fallback
to a different architecture.

The GPU measurements used Sentence Transformers 5.4.1 and Transformers 5.7.0;
pin those versions when reproducing the trial. The core package declares minimum
requirements, so a fresh installation can resolve newer versions.

Native index identity covers the model, revision, encoding routes, precision,
attention/pooling policy, saved query prompt, normalization, and context cap.
The LanceDB table stores that identity alongside its vectors. A changed or
unknown contract blocks reads and writes, including same-dimension model
changes and reopening through an older configuration. Restore the matching
configuration or rebuild offline; a missing sidecar never authorizes reuse of
unidentified vectors for native encoding.

Use an explicit project scope and an offline rebuild when replacing an
embedding contract. The v1 server refuses native configurations; use
`mainframe serve` and `mainframe-mcp`. Harrier is the default following the
[measured comparison](MODEL_COMPARISON.md). Qwen3-Reranker-0.6B BF16 is the
selected evaluation reranker; its pinned contract and measurement scope are in
its [separate comparison](RERANKER_COMPARISON.md). A reranker change reorders
existing candidates and does not require re-embedding. Pacing belongs to
evaluation; normal daemon inference is unpaced. Check desktop responsiveness
during ordinary use.

## Startup memory diagnostics

Windows error 1455 (`ERROR_COMMITMENT_LIMIT`) concerns host system commit
capacity: RAM plus page file backing. Available physical RAM and free VRAM
do not show the remaining commit budget. Check **Task Manager > Performance >
Memory > Committed** during startup. Close memory-heavy processes or adjust
page file capacity before retrying. See Microsoft's [error-code definition](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1300-1699-)
and [commit accounting](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-performance_information).

Check whether the page file is already system-managed before changing it. Growth
requires disk space; sizing depends on peak system commit and crash-dump needs,
not a universal RAM multiplier. If headroom is tight, reduce concurrent workloads
or narrow the indexed corpus before increasing system commit. Consult Microsoft's
[page-file guidance](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows)
before making machine-wide changes.

v2 recognizes native and wrapped 1455 errors, including explicit exception
causes. Logs, failed model status (`guidance`), and `model.failed` events carry
the explanation without changing the original error or load-failure backoff.
Host capacity failures do not trigger CUDA-context recovery. A failed primary
embedding load releases its model references, collects cycles, and clears the
CUDA allocator cache before the existing quantized fallback. It preserves the
configured models and quantization; it cannot create system capacity.

Measure fresh-process indexing, first search after indexing, and warm search
separately. The first search can include reranker loading. Record system commit
headroom and process private bytes alongside timings; repeat under comparable
host load before drawing performance conclusions. The validation report records
timings, while host memory measurements require a separate monitor.

## Code and validation

| Directory | Responsibility |
|---|---|
| `src/mainframe/core/` | Chunking, models, indexing pipeline, store, search |
| `src/mainframe/memory/` | Lane discovery, immutable captures, receipts |
| `src/mainframe/service/` | Process ownership, watcher, scheduler, REST, events |
| `src/mainframe/adapters/` | CLI, HTTP MCP, stdio forwarding |
| `src/mainframe/app.py` | Composition and shared read/write entry points |

Run `python -m pytest tests/ -q` for both versions and public-audit regressions.
The suite uses fake models and temporary stores, with real watcher and transport
coverage. For live verification, use a separate `mainframe_dir`, a synthetic
project, and an unused port. Check startup, search, watcher create/update/delete,
capture visibility, restart reuse, and offline rebuild. Do not share an active
GPU model allocation with another heavy process.

See [evaluation instructions](../eval/README.md) for corpus comparison and
daemon scoring. Automated tests establish behavior, not retrieval quality;
quality claims require a measured corpus and query set.

## Repeatable live validation

`mainframe validate --output ~/mainframe-validation/run-01` runs a synthetic
smoke check through REST, including a fresh daemon process and restart. Add
`--duration 1800` for an observation window with repeated queries and file/capture
cycles. A cycle already in progress finishes before shutdown; no new cycle
starts after its observation phase expires. Use `--timeout SECONDS` to change
the default 2400-second indexing/visibility bound. Health probes use a fixed
3-second timeout. A failed check returns a nonzero exit code.

The output must be new and outside every Git worktree. The runner replaces all
indexing paths with synthetic scratch state, preserves only the model cache path,
and never attaches to or shuts down an existing daemon. It stops its own child
after checking a fresh launch nonce in discovery and health, so Windows venv
launcher/interpreter PID differences do not prevent readiness or orderly shutdown.
Cleanup also runs on failure; a child that cannot shut down within the configured shutdown
bound is terminated and the validation fails. Scratch files remain for diagnosis.

`report.json` has a versioned schema and records the runtime version, model names,
startup readiness, initial indexing, first-search and warm-search timings, health
latency, mutation counts, restart reuse, and errors. The first search follows
indexing and may load the reranker; it is not a cold embedder measurement. Longer
runs sample queue depth, row counts, and VRAM. Periodic rescans use an accelerated
three-minute interval for validation only. Reports use synthetic content and do
not measure retrieval quality. Raw reports, generated credentials, and logs stay
local; manually review and scan any publication.
