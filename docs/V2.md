# v2 Daemon Preview

v2 runs one local service for indexing, search, and capture across MCP clients.
The existing `mainframe_mcp.server` remains the default v1 stdio server. v2
currently supports capture, indexing, and search; consolidation, contradiction
detection, and RAPTOR remain v1 features.

## Configure and start

Install with `python -m pip install -e ".[test]"`. Configure project scope before
starting: an empty `paths.include_projects` includes every eligible repository
under `paths.repos_dir`. Includes and excludes accept project-name globs.

A minimal configuration for an isolated deployment:

```json
{
  "paths": {
    "mainframe_dir": "~/.local/share/mainframe-v2",
    "repos_dir": "~/repos",
    "include_projects": ["example-project"]
  },
  "service": {"port": 7433}
}
```

Point `MAINFRAME_CONFIG` at that JSON file in every server and client shell.
For example, PowerShell uses `$env:MAINFRAME_CONFIG = "./config.json"`; POSIX
shells use `export MAINFRAME_CONFIG=./config.json`. Paths expand `~`. Without
an override, configuration lives at `~/.claude/mainframe/config.json`.
Invalid JSON and unknown configuration keys prevent startup. Hardware presets
in `configs/` can be selected through `MAINFRAME_PRESET` in a source checkout.

```bash
mainframe serve
# In another shell with the same configuration:
mainframe status
mainframe search "embedding batch size" --detailed
mainframe events --tail 20
mainframe down
```

Models load on demand; `service.prewarm: true` loads them at startup. Health
checks stay responsive during model loading. `mainframe serve` works on Windows
and POSIX. Windows users using the default configuration location can install
a logon task with `mainframe install-task` and start it with `mainframe up`.
Use `mainframe install-task --dry-run` to write and inspect the task XML first.

## Connect clients

Register `http://127.0.0.1:7433/mcp` as a Streamable HTTP MCP server, using the
configured port. The full endpoint exposes `search`, `capture`, `status`, and
`maintain`. `/mcp/ro` exposes only `search` and `status`.

For hosts that require stdio:

```bash
python -u -m mainframe.adapters.mcp_stdio_shim
```

The shim forwards to the full `/mcp` endpoint without loading another set of
models. Use HTTP `/mcp/ro` when the client needs read-only access. v1's
`MAINFRAME_READ_ONLY` and `MAINFRAME_PREWARM` variables do not configure v2.

The REST surface includes `GET /healthz`, `/status`, `/events` and
`POST /search`, `/capture`, `/jobs/{kind}`, `/shutdown`. Maintenance jobs are
`index`/`rescan`, `optimize`, and `reload`; `index` aliases `rescan`.

The service binds to loopback and checks the Host header. On shared machines,
set `service.token`; all routes then require `Authorization: Bearer <token>`.
The CLI and shim read that token from configuration; HTTP MCP clients must send
the header themselves. Keep configuration and event logs outside public Git.

## Files, captures, and citations

Markdown files are authoritative. The knowledge lane discovers root context
files, documentation, research notes, and the local library. Project filters
and symlink containment checks apply during scans and watcher processing.

`mainframe capture --file note.md --project example-project --title "Decision"`
writes an immutable, secret-scrubbed capture under
`<mainframe_dir>/captures/<project>/`. The watcher indexes it after debounce;
periodic rescans recover missed notifications. Captures are excluded from
ordinary search; opt in with `--sessions` or `include_sessions=true`.

Search returns confidence and reranker scores. Detailed results include text,
character offsets, and truncation status; `response_format="full"` returns the
whole chunk for evaluation. Line citations require a matching file revision
and a verifiable passage. Ambiguous or changed passages receive no line span.
Existing merged-heading captures can regain correct spans without reindexing.

## Index ownership and recovery

v2 uses `<mainframe_dir>/index.lancedb`; v1 continues using `.lancedb`. The first
v2 start builds a fresh index. A process lock excludes concurrent daemon and
offline writers. Mutations run through one queue; shutdown retains ownership
until the active writer finishes. A second instance exits with code 3.

The index records the settings that produced it. Changed index settings block
indexing and appear in `status.index.config_drift`; embedding changes also
block incompatible searches. Update configuration, then use:

```bash
mainframe down
mainframe rebuild
mainframe serve
```

Rebuild drops and recreates only the v2 index. It refuses while a daemon owns
the lock. Restart after configuration edits; `mainframe reload` releases
models and clears load-failure backoff, rather than rereading configuration.
Recognized device failures trigger one model reload and retry. Repeated load
failures back off, while file and job failures remain visible in events.

## Code and validation

| Directory | Responsibility |
|---|---|
| `src/mainframe/core/` | Chunking, models, indexing pipeline, store, search |
| `src/mainframe/memory/` | Lane discovery, immutable captures, receipts |
| `src/mainframe/service/` | Process ownership, watcher, scheduler, REST, events |
| `src/mainframe/adapters/` | CLI, HTTP MCP, stdio forwarding |
| `src/mainframe/app.py` | Composition and shared read/write entry points |

Run `python -m pytest tests/ -q` for both versions and public-audit regressions.
The suite uses fake models and temporary stores, with real watcher and transport
coverage. For live verification, use a separate `mainframe_dir`, a synthetic
project, and an unused port. Check startup, search, watcher create/update/delete,
capture visibility, restart reuse, and offline rebuild. Do not share an active
GPU model allocation with another heavy process.

See [evaluation instructions](../eval/README.md) for corpus comparison and
daemon scoring. Automated tests establish behavior, not retrieval quality;
quality claims require a measured corpus and query set.
